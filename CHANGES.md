# Доработки по замечаниям заказчика

Нумерация пунктов совпадает со списком правок из переписки.

## Что сделано

**1. «Сотрудники» → «Обучающиеся».** Переименованы меню, заголовки, подписи, сообщения, выгрузки. Адреса страниц (`/People`) не менялись, закладки продолжают работать. Данные и функции прежние.

**2. Карточка обучающегося.**
- Поле «СНИЛС» (проверка длины и контрольного числа, единый вид `123-456-789 01`).
- Раздел «Документы»: паспорт, СНИЛС, диплом и «другой документ» с названием. Номер СНИЛС и файл СНИЛС хранятся независимо. Паспорт, СНИЛС и диплом в одном экземпляре (новый файл заменяет старый), «другие» можно добавлять сколько нужно.
- У программы появились «Обязательные данные для зачисления» (дата рождения, СНИЛС, телефон, почта, организация, должность, сканы паспорта / СНИЛС / диплома). Если чего-то нет, зачисление блокируется и показывается список недостающего. У существующих программ обязательных полей нет, поведение прежнее, пока их не отметят. Для новых программ по умолчанию отмечены дата рождения и СНИЛС.

**3. Документы по шаблонам УМЦ** (страница группы → «Документы группы»; Word):
- приказ о зачислении;
- приказ об отчислении в связи с завершением обучения;
- приказ об отчислении по иным основаниям (собран на основе шаблона приказа об окончании, образца от заказчика нет);
- протокол аттестационной комиссии (в протокол попадают слушатели с положительным результатом или без оценки);
- ведомость итоговой аттестации (образца нет, форма простая);
- список слушателей (Word и Excel).

Всё, чего нет в системе (номер и дата приказа, куратор, часы, комиссия), вводится вручную прямо в форме, а то, что остаётся пустым, в документе остаётся подчёркиванием для дописывания. Состав комиссии, регистрационный номер и куратор запоминаются в группе. Каждый сформированный документ сохраняется, виден в списке группы и пишется в историю. Приказ об отчислении по иным основаниям при желании сразу переводит слушателя в статус «Отчислен» с причиной и датой.

**3.7. Реестр выданных документов.** Предварительный вариант: страница «Отчёты» → выгрузка → «Реестр выданных документов» (записи с номером удостоверения: №, ФИО, организация, программа, группа, номер, дата). Окончательная форма ждёт ответа заказчика, вопросы ниже.

**3.8. Сводная отчётность.** Страница «Отчёты»: сводки по программам, организациям и периодам (месяц начала обучения) с числом обучающихся, прошедших, отчисленных и по ГЗ / ПД. Отбор по ФИО / СНИЛС, организации, программе, группе, периоду, финансированию, статусу, номеру удостоверения. Сводка выгружается в Excel.

**4. ГЗ и ПД.** Признак на группе и на обучающемся в группе. Приоритет: если указан у обучающегося, он главнее группового. Новые зачисления наследуют признак группы. Учитывается в сводках и фильтрах.

**5. Дубли.** При создании и при изменении ФИО / даты рождения / СНИЛС / почты система ищет совпадения (СНИЛС в любой записи, ФИО + дата рождения, ФИО без даты, почта) и показывает записи со ссылкой. Сохранить можно только подтвердив, что это другой человек (можно написать пояснение), это попадает в историю.

**6. Импорт из Excel.** «Обучающиеся» → «Загрузить из Excel». Скачивается шаблон, загруженный файл проверяется (структура, обязательные поля, даты, СНИЛС, почта, ИНН, организации), показывается предпросмотр с ошибками по строкам и полям и возможными дублями. Только после подтверждения записи добавляются, ошибочные не загружаются никогда, дубли по умолчанию пропускаются (можно отметить, что это другие люди). После загрузки отчёт: добавлено / пропущено / ошибки. Организация должна уже быть в справочнике (по ИНН или названию).

**7. История и права.**
- История (раздел «История изменений», раньше «Журнал действий» у администратора) показывает пользователя, дату и время, действие, объект и что именно изменилось («поле: было → стало»). Фиксируются создание, изменение, удаление, зачисление, исключение, отчисление, формирование документов, просмотр документов обучающихся, выгрузки и импорт.
- Новые права методиста (настраиваются в карточке пользователя): зачисление и отчисление, просмотр документов, загрузка и удаление документов, формирование документов и отчётов, просмотр истории. Существующие методисты сохраняют все прежние возможности, кроме просмотра истории (его выдаёт администратор). После обновления всем придётся один раз войти заново.
- Без права просмотра документов скрыты файлы, СНИЛС (в карточке показываются только последние две цифры), дата рождения, телефон и почта в выгрузках.

**8. Поиск и фильтры.** Список обучающихся: ФИО, телефон, почта, организация, СНИЛС (при праве просмотра документов), организация, программа, период обучения, номер удостоверения, финансирование, образование. Все условия работают вместе (для курса: программа, период, номер и финансирование проверяются по одной и той же записи об обучении).

**9. Выгрузка.** «Отчёты» → «Выгрузка»: отмечаете нужные поля, выбираете Excel или Word. Личные поля доступны только с правом просмотра документов.

## Как обновить

1. Сделайте резервную копию базы.
2. Запустите приложение, миграция `Revisions` применится при старте (или `dotnet ef database update`).
3. Заполните обязательные данные в программах.
4. Шаблоны Word встроены в приложение. Чтобы поставить свои, положите файлы с теми же именами (`enrollment-order.docx`, `completion-order.docx`, `attestation-protocol.docx`) в `App_Data/templates` (папку можно сменить в настройке `Storage:TemplatesFolder`).

## Проверка

- Добавлены автотесты (СНИЛС, обязательные поля, дубли, ГЗ / ПД, разбор Excel, отчёты, формирование приказов и протокола).
- Приказы и протокол сверены визуально с шаблонами.
